# AI-функции FuturePath AI: как это устроено

## Что есть на сайте

Страница `/ai`, три функции:
1. **Анализ результата** (`POST /api/ai/analysis`): сильные стороны, интересы и навыки.
2. **План развития на 30 дней** (`POST /api/ai/roadmap`): 30 заданий. Каждая карта получает свой id, и отметки привязаны к нему.
3. **Симулятор профессии** (`POST /api/ai/simulator`): что ИИ может взять на себя в выбранной профессии и какие навыки останутся важными.

Кнопка «Объяснить результат» на странице результата — отдельная, старая функция (`POST /api/ai`).

## Статус интеграции (честно)

- Ключ API пока не подключён. Поэтому **реальный ответ модели не получался**.
- Что проверено: весь путь запроса (заголовки, тело, разбор ответа) через локальный HTTP-имитатор провайдера в тестах; резервный режим в браузере; `api.anthropic.com` отвечает HTTP 401 на запрос без ключа (адрес и формат доступны, но ИИ не работал).
- Когда появится ключ: см. раздел «Как подключить» ниже и обязательно проверить один запрос.

## 1. Как сайт отправляет запрос ИИ

1. Браузер нажимает кнопку и отправляет **пустой запрос** на наш сервер (например, `POST /api/ai/analysis`). Браузер не передаёт ни данные теста, ни ключ.
2. Сервер сам читает профиль из cookie и **актуальный результат из базы**.
3. Сервер строит промпт (`src/backend/ai/prompts.ts`): правила + JSON с данными результата.
4. `src/backend/ai/provider.ts` отправляет запрос провайдеру (Anthropic или OpenAI-совместимый API) с ключом из `.env`. Таймаут 20 секунд.
5. Ответ проходит проверку (см. п. 4). Если что-то не так, сработает резерв.

Ключ только в заголовке запроса на сервере (`x-api-key` или `Authorization`), в тело и в браузер он не попадает. Тест проверяет, что ключа нет в теле.

## 2. Какие данные передаются

Только то, что нужно для анализа:
- названия шести направлений и их проценты;
- тексты трёх-четырёх выбранных ответов, которые дали баллы топ-направлениям;
- названия пяти профессий из расчёта;
- для симулятора: описание выбранной профессии из каталога.

**Не передаются:** имя профиля, id профиля, cookie, e-mail, полные ответы в виде id, ключ API.

Точный текст можно посмотреть в коде: `resultData()` в `src/backend/ai/prompts.ts`.

## 3. Как модель формирует ответ

Модели задано:
- роль помощника по профориентации для школьников Казахстана, отвечать по-русски и просто;
- использовать **только переданные данные**;
- **не придумывать** статистику, цифры, зарплаты и данные о рынке труда;
- прогнозы описывать как предположения, а не как факты;
- **не менять** результаты теста: баллы уже подсчитаны;
- вернуть **только JSON** заданной формы (например, для карты: ровно 30 объектов `day/title/task`).

Модель — это генератор текста. Она не считает баллы: баллы и топ-3 считает код, без ИИ.

## 4. Как ответ проверяется и отображается

Проверка в три шага:
1. **Извлечение JSON** (`src/backend/ai/json.ts`): берём объект из блока ```json``` или из текста. Если JSON нет или он не читается, это ошибка.
2. **Проверка структуры** (`src/backend/ai/schemas.ts`):
   - все нужные поля на месте, списки нужной длины;
   - для карты ровно 30 дней с номерами 1…30 по порядку;
   - длинные строки обрезаются;
   - фразы с процентами, зарплатами, тенге и «прогнозами рынка» **отклоняются**.
3. **Резерв**: если проверка не прошла, ошибка провайдера, таймаут или лимит запросов, показывается текст по правилам (`src/backend/ai/fallback.ts`). В интерфейсе стоит плашка:
   - «Ответ ИИ · провайдер / модель» — если ответ модели прошёл проверку;
   - «Резервный режим, это не ответ ИИ» с причиной — во всех остальных случаях.

Результат ИИ сохраняется в таблицу `AiRecord` с пометкой `source = "ai"` или `"rules"`. Баллы теста в эту таблицу не пишутся вообще.

Отображение: `src/components/AiWorkspace.tsx`. Внизу каждого блока стоит предупреждение, что это не факт и не прогноз рынка труда.

## 5. Чем алгоритм теста отличается от ИИ

| | Алгоритм теста | ИИ (языковая модель) |
|---|---|---|
| Что делает | Складывает баллы по заранее заданным весам | Пишет текст по данным и правилам |
| Результат | Всегда одинаковый для одинаковых ответов | Может отличаться от раза к разу |
| Где находится | `src/recommendation-engine/index.ts`, без сети | `src/backend/ai/` и внешний провайдер |
| Можно ли объяснить | Да: каждый балл виден по вопросу | Нельзя полностью: модель «черный ящик» |
| Может ли ошибаться | Может, если неверно заданы веса | Может выдумать, поэтому мы проверяем структуру и запрещаем цифры |
| Влияет на баллы | Это и есть источник баллов | **Нет**, ИИ не может изменить баллы |

Короткая формула для жюри: **баллы считает код по правилам, а ИИ только объясняет уже подсчитанное и предлагает задания.**

## Как подключить ключ

В файле `.env` (его нет в Git):

```
AI_PROVIDER="anthropic"
AI_API_KEY="ваш_ключ"
AI_MODEL="имя_модели"
AI_RATE_LIMIT_PER_HOUR="10"
```

Перезапустите сервер. Затем нажмите кнопку на `/ai` и проверьте, что появилась плашка «Ответ ИИ · anthropic / …», а не резерв. Если плашка резервная, причина написана в ней.

Ключ нельзя вставлять в код, писать в переменные `NEXT_PUBLIC_*` или коммитить `.env`.

## Лимиты

- `AI_RATE_LIMIT_PER_HOUR` — запросов к ИИ в час на профиль, общий для трёх функций.
- Лимит тратится **только когда ИИ подключён**. Резервный режим лимит не тратит.
- Счётчик хранится в памяти сервера: после перезапуска обнуляется.
