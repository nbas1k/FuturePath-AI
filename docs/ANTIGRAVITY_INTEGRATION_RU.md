# Подключение Antigravity Tools к FuturePath AI

Этот документ описывает, как проект обращается к локальному прокси Antigravity Tools, что проверено и что ещё нужно сделать.

## 1. Что подключено

Antigravity Tools добавлен как провайдер `antigravity` (файл `src/backend/ai/config.ts`). Он работает так же, как и остальные AI-функции сайта:
- анализ результата (`POST /api/ai/analysis`): сильные стороны, интересы, навыки, **недостающие компетенции**, **виды образовательных ресурсов**;
- дорожная карта на 30 дней (`POST /api/ai/roadmap`);
- объяснение влияния ИИ на профессию (`POST /api/ai/simulator`).

Старые провайдеры (`anthropic`, `openai`, `openai-compatible`) сохранены. Если прокси не отвечает, ключа нет или ответ не прошёл проверку, сайт показывает резервный текст по правилам.

**Пока не подтверждено:** название модели и ответ прокси. Прокси отвечает HTTP 401 на любой запрос без ключа, поэтому реальный вызов модели ещё не выполнялся. Название модели задаётся переменной `ANTIGRAVITY_MODEL` и известно только после подключения ключа.

## 2. Переменные окружения

В файле `.env` (он не попадает в Git):

```
AI_PROVIDER="antigravity"
ANTIGRAVITY_API_URL="http://127.0.0.1:8045/v1"
ANTIGRAVITY_API_KEY="ваш_ключ_из_antigravity"
ANTIGRAVITY_MODEL="имя_модели"
AI_TIMEOUT_MS="60000"
```

- `ANTIGRAVITY_API_URL` — по умолчанию `http://127.0.0.1:8045/v1`, менять не нужно для локальной работы.
- `ANTIGRAVITY_API_KEY` — ключ прокси. В код, в браузер и в журнал он не попадает: проверено тестом (ключа нет ни в теле запроса, ни в сообщениях об ошибках).
- `ANTIGRAVITY_MODEL` — модель, которую отдаёт прокси. Список моделей можно получить запросом `GET /v1/models` с ключом.
- `AI_TIMEOUT_MS` — сколько ждать ответа (от 5 до 120 секунд).

Проверка, что ключ подхвачен, без показа его значения: на странице `/ai` при успешном ответе появится плашка «Ответ ИИ · Antigravity Tools / имя модели». Если появилась резервная плашка, причина написана в ней.

## 3. Запуск на вашем компьютере

1. Запустите Antigravity Tools и убедитесь, что прокси слушает `127.0.0.1:8045`.
2. Впишите ключ и модель в `.env` (см. пункт 2).
3. Запустите сайт:

```bash
npm run dev
```

4. Откройте http://localhost:3001/ai, пройдите тест и нажмите кнопки на странице.

Если прокси не запущен, сайт не падает: появится резервный режим с причиной «Не удалось связаться с провайдером ИИ».

## 4. Удалённый сайт и Vercel

- **Vercel не может обратиться к `127.0.0.1` вашего компьютера.** Адрес `127.0.0.1` на сервере Vercel указывает на сам сервер Vercel, где прокси нет.
- Для публичного сайта нужен **защищённый туннель** от Vercel к вашему прокси (например, Cloudflare Tunnel или аналогичный). Туннель должен требовать аутентификацию, а ключ прокси должен оставаться секретом в переменных окружения Vercel.
- **Не публикуйте прокси в интернет без защиты.** Без туннеля с аутентификацией через интернет прокси открывать нельзя.
- Пока публичного запуска не делаем: по вашему требованию сначала проверяем локально.

## 5. Безопасность

- Ключ хранится только в `.env` на сервере. Файл в `.gitignore`.
- Браузер получает только результаты ИИ, но не ключ и не адрес прокси.
- В запрос к модели уходят направления, проценты, тексты выбранных ответов и названия профессий. **Имя, id профиля, cookie и e-mail не уходят.**
- Модели запрещено выдумывать статистику, зарплаты и прогнозы рынка труда. Проверка структуры отклоняет ответы, где есть проценты, зарплаты, тенге и ссылки.
- Ссылки запрещены полностью: их легко выдумать. Ресурсы даются только как виды обучения («курсы по основам программирования»).
- Лимит запросов: `AI_RATE_LIMIT_PER_HOUR` на профиль (по умолчанию 10 в час). Резервный режим лимит не тратит.
- Настройки аккаунта Antigravity Tools не менялись, ограничения провайдера не обходились.

## 6. Что проверено

| Проверка | Как | Результат |
|---|---|---|
| Настройки `ANTIGRAVITY_*` | `tests/antigravity.test.ts` | адрес по умолчанию, переопределение, выключение без ключа, таймаут |
| Путь запроса, Bearer-ключ, модель | HTTP к локальному имитатору | ключ в заголовке, не в теле |
| Разбор JSON из ответа модели | имитатор | принимается JSON в блоке ```json``` |
| Выдуманная ссылка в ответе | имитатор | отклоняется, уходит в резерв |
| 401 / 429 / 500 от прокси | имитатор | понятные причины, тела ошибок не выводятся |
| Таймаут | имитатор с задержкой | код timeout, резерв |
| Прокси не запущен | порт без сервера | резерв «не удалось связаться» |
| Пустой ответ | имитатор | код empty |
| Реальный прокси | `GET /v1/models` без ключа | HTTP 401 — прокси отвечает, но ключа нет |

**Не проверено:** реальный ответ модели Antigravity Tools. Причина: ключа нет в окружении и в `.env`. Как только вы добавите ключ, нужно выполнить проверку (см. пункт 7).

## 7. Как проверить реальный ответ после добавления ключа

1. Заполните `.env` (пункт 2) и запустите `npm run dev`.
2. Откройте `/ai`, нажмите «Сделать анализ». Ожидаемо: плашка «Ответ ИИ · Antigravity Tools». Если появилась резервная плашка, в ней написана причина (401 — ключ не принят, таймаут, ошибка структуры и т. п.).
3. Нажмите «Создать карту» и «Смоделировать». Так же проверьте плашки.
4. Сообщите результат: какая модель отвечала и какие плашки появились.

## 8. Что осталось до публичного запуска

- Получить и проверить реальный ключ и модель (см. пункт 7).
- Выбрать способ безопасного туннеля или хостинг, где прокси доступен, и настроить аутентификацию.
- Решить, как хранить ключ на хостинге (переменные окружения платформы, а не файлы в репозитории).
- Ограничить лимиты на уровне прокси (они в Antigravity Tools, мы их не меняли).
- Пересмотреть лимит запросов в памяти: при нескольких серверах счётчики будут разными.

## 9. Что НЕ сделано в этой версии

- **ИИ не выбирает профессии из каталога.** Подбор профессий и совпадения считаются правилами (`recommendation-engine`), это не ответ модели. Сделать ИИ-подбор можно, но тогда нужна отдельная проверка.
- **Перспективы рынка труда** модель описывает только качественно, как тенденции и предположения. Данных о спросе, зарплатах и вакансиях в проекте нет и не будет без проверенных источников.
- **Навыки человека** модель оценивает только по ответам теста. Это не измеренный уровень, так и написано в интерфейсе.
