# Проблема, алгоритм и ИИ-интеграция

## Проблема

Выбор профессии в школе и на первых курсах часто делается наугад: профессий много, понятных описаний «чем человек занимается каждый день» мало, а искусственный интеллект меняет содержание многих профессий. Школьнику трудно понять, какие его интересы к чему ведут и какие навыки останутся ценными рядом с ИИ.

FuturePath AI — учебный прототип, который помогает сделать первый шаг: собрать интересы в понятную картину, показать профессии с честным описанием влияния ИИ и превратить размышления в план из 30 небольших действий. Решение не заменяет консультацию специалиста и не претендует на научную диагностику.

## Алгоритм (модуль `recommendation-engine`)

Вход: ответы `{ q1: "a", ..., q18: "d" }`. Выход: баллы направлений, топ-3, список профессий.

1. **Проверка**: есть ответ на каждый вопрос, вариант существует (`validateAnswers`).
2. **Баллы направления**: сумма `scores` выбранных вариантов. Вклад каждого ответа запоминается (для объяснения).
3. **Нормировка**: `percent = score / max × 100`, где `max` — сумма максимальных баллов направления по всем вопросам. Это нужно, потому что у направлений разное число «шансов» набрать баллы.
4. **Топ-3**: сортировка по убыванию доли; при равенстве — порядок в `directions.ts` (поэтому результат детерминирован).
5. **Профессии**: у профессии заданы веса направлений (1 — основное, 0.5 — дополнительное); оценка = средневзвешенный процент пользователя. Сортировка по убыванию, при равенстве — по названию.
6. **Объяснение без ИИ** (`explainTop`): перечисление трёх самых весомых ответов для каждого направления.

Свойства: воспроизводимость (нет случайности), прозрачность (виден вклад ответов), независимость от ИИ.
Ограничения: баллы в вариантах назначены авторами вручную, это не калиброванная модель; 18 вопросов дают грубую оценку.

## ИИ-интеграция (модуль `src/backend/ai`)

**Роль ИИ**: написать персональное текстовое объяснение по уже посчитанным результатам. ИИ не считает баллы и не выбирает профессии.

**Поток**: кнопка на `/result` → `POST /api/ai` → сервер находит профиль и последний результат → `prompt.ts` собирает запрос → `provider.ts` обращается к выбранному провайдеру → ответ показывается с пометкой провайдера и модели.

**Запрос**: system — роль помощника, просьба писать просто и коротко, не выдумывать статистику и зарплаты, напомнить, что тест не диагностика. user — топ-3 направления с баллами и тремя самыми влиятельными ответами, три лучшие профессии, просьба объяснить, предложить 2 способа проверить интерес и назвать нужные человеческие навыки. Имя и другие личные данные не отправляются.

**Конфигурация** (`.env`, см. `.env.example`): `AI_PROVIDER` (`none` / `anthropic` / `openai` / `openai-compatible`), `AI_API_KEY`, `AI_MODEL`, `AI_BASE_URL`, `AI_RATE_LIMIT_PER_HOUR`. ИИ включён, только если заданы провайдер, ключ и модель.

**Безопасность**: ключ только на сервере; в браузер не попадает; `.env` в `.gitignore`.

**Обработка ошибок**: таймаут 20 с; коды `auth` (401/403), `rate` (429), `upstream` (прочее/сеть), `empty` (пустой ответ), `disabled`. Любая ошибка → резервный режим.

**Лимит**: `AI_RATE_LIMIT_PER_HOUR` запросов в час на профиль (в памяти сервера).

**Резервный режим**: показывается текст `explainTop` с плашкой «Резервный режим — это не ответ ИИ» и причиной. Ответ ИИ никогда не имитируется.

**Статус проверки**: реальный вызов провайдера не выполнялся (ключа не было); логика проверена тестами на подменённом `fetch`.
